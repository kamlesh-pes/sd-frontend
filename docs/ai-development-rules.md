 # AI Development Rules

 1. Specification is authoritative.
 2. Existing code is authoritative for established implementation conventions.
 3. Never invent missing requirements.
 4. Ask when a business rule is ambiguous.
 5. Never silently change API contracts.
 6. Never silently change database schema.
 7. Never weaken security to solve functional issues.
 8. Never remove or weaken tests to make them pass.
 9. Do not modify unrelated files.
 10. Prefer the smallest change that satisfies the requirement.
 11. Reuse existing dependencies and patterns.
 12. Every feature requires tests.
 13. Every security-sensitive change requires security review.
 14. Every API change requires API documentation update.
 15. Every database change requires migration.
 16. Every completed task must be validated against acceptance criteria.
